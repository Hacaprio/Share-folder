# 프로젝트 등록 및 운영 안내

## 새 프로젝트 추가

1. 앱은 apps/<project-name>/, 자동화는 automations/<project-name>/ 폴더를 만듭니다.
2. templates/project/README.md와 .env.example을 복사하고 실제 프로젝트에 맞게 수정합니다.
3. 소스와 의존성 명세를 넣고 사용하는 런타임 버전을 README에 기록합니다.
4. 의존성 잠금 파일은 Git에 포함하고 설치된 의존성 폴더는 제외합니다.
5. 루트 README의 프로젝트 목록에 상대 링크와 설명을 추가합니다.
6. 별도 빈 폴더에서 설치·실행하여 필요한 파일이 빠지지 않았는지 확인합니다.
7. git status와 git diff --cached를 확인하고, 의도한 파일만 커밋하여 main에 게시합니다.

하위 프로젝트 안에서 git init을 실행하지 않습니다.
기존 Git 저장소를 가져올 때에는 .git 디렉터리를 그대로 중첩해 복사하지 말고,
이력 보존 여부를 먼저 정한 다음 가져옵니다. 공개 범위가 다른 프로젝트는 별도 저장소를 사용합니다.

## 환경 설정과 데이터

- 실제 비밀값은 .env에 보관하고 이름과 설명만 .env.example에 기록합니다.
- 기본 .gitignore는 일반적인 비밀 파일·캐시·빌드 결과를 제외하지만 모든 민감 파일을 탐지하지는 않습니다.
- git check-ignore -v <파일경로>로 제외 규칙을 확인합니다.
- 이미 커밋한 파일은 .gitignore만 추가해도 과거 기록에서 없어지지 않습니다.
- 비밀값이 게시되었다면 먼저 해당 키나 비밀번호를 폐기·교체하고 기록 정리를 진행합니다.
- 데이터베이스, 실제 고객 데이터, 로그, 생성 결과는 저장소 밖 또는 runtime-data/에서 관리합니다.
- 배포용 대용량 파일은 GitHub Releases나 별도 저장소를 사용하고, 버전 관리가 필요하면 Git LFS를 검토합니다.

## 읽기 전용 공유

공개 저장소의 일반 방문자는 읽기·다운로드·Fork가 가능합니다.
원본에 직접 쓰는 권한을 주려면 별도로 협업자를 추가해야 하므로 이 저장소에는 쓰기 협업자를 추가하지 않습니다.
Fork에서 수정한 내용은 원본에 자동 반영되지 않습니다.
Pull request가 제출되더라도 병합 여부는 소유자가 결정합니다.
소유자의 관리·수정 권한은 유지합니다.

## 자동화 실행

예약 실행은 기본으로 활성화하지 않습니다.
각 자동화의 동작이 정해진 뒤 Mac의 launchd, 서버 스케줄러, GitHub Actions 중 맞는 환경을 선택합니다.
외부 계정·기기·로컬 파일에 접근해야 한다면 실행 환경과 인증 방식을 먼저 문서화합니다.
GitHub Actions를 추가할 경우 워크플로의 기본 권한은 contents: read로 두고 필요한 작업에만 추가 권한을 부여합니다.

## 버전 및 변경 관리

main은 공유 가능한 상태로 유지합니다.
변경 설명을 남기고 필요한 설치·실행 검증을 수행한 후 게시합니다.
실제 앱 배포 시 프로젝트별 태그(예: my-app-v1.0.0)와 변경 내역을 사용합니다.
서로 다른 공개 범위나 관리 권한이 필요해지면 해당 프로젝트를 독립 저장소로 분리합니다.

## 이용 조건

현재 오픈소스 라이선스는 부여하지 않았습니다.
향후 재사용·수정·재배포 허용 범위를 정한 뒤 적절한 라이선스를 추가합니다.
외부에서 가져온 코드와 자산은 원래 라이선스 및 출처를 함께 기록합니다.
